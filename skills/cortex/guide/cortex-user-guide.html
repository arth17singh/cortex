CORTEX user guide

Layered project memory that keeps itself up to date and gets better on its own, so you can clear a chat or open a new one without losing anything.

The short version

In each project folder, run /cortex all once (or /cortex start if past chats don't matter). After that, every chat records itself, built-in hooks keep it on track, and memory repairs its own blind spots. You don't re-run anything to capture new work.

Project set up with an older version? Run /cortex upgrade there once.

How it works

Memory lives in a memory/ folder inside each project, split into layers. A new chat automatically loads only the top layer: the rules, current status, and a map of every topic file and recent session log. It opens deeper layers only when a task needs them. The history stays in the deeper layers, so each start stays cheap. /cortex status shows your numbers.

It records as you work

Each chat keeps a session log and updates the topic files right after anything worth keeping: decisions, findings, fixes, your corrections, useful explanations.

It knows what it already has

A ledger records, line by line, which parts of which chats are already in memory, so nothing is ever processed twice.

Hooks keep it honest

Two small Claude Code hooks run automatically. When a chat starts, one tells Claude which chat it is, what needs recovering, and whether memory needs tidying or a self-test. When Claude finishes a reply, the other reminds it if memory has fallen behind. Hooks never mark anything as recorded themselves.

It reads smartly, and checks before acting

Claude picks 1–3 topic files by the words on the map, reads only the matching lines of session logs, and opens at most 4 files per question. Before editing code, stating a fact or recommending something, it checks memory, including options that were already rejected, so it doesn't re-propose them. It trusts the code first and cites its sources.

It stays bounded, without forgetting

The always-loaded map is hierarchical: the newest 15 session logs get their own line, older ones are summed up in week, month and quarter lines, and big folders get a one-line summary of their key nouns. When a limit is crossed, Claude moves detail one layer down and leaves a pointer. It backs up first and never deletes, so the start-up cost levels off even in very busy projects, but nothing is lost.

You stay in control

Pause a chat, exclude one, make memory forget something, or switch recording to manual. Anything big shows you a plan first and waits for your OK.

And it improves itself: see Memory that improves itself.

Commands

Every command starts with /cortex. Commands marked asks first show you exactly what will happen and wait for your OK. Add --yes to skip the question.

Set up and capture

/cortex start

this chat only

Records this chat from now on. No past chats are read.

  • If the project has no memory yet, it builds a starter version from the docs and code, then asks for the recording mode (auto or manual) and whether to commit memory/ to git (default: no).
  • The part of this chat before the command is marked skipped, so /cortex all won't pull it in later.

Option: --from-chat-start also captures what was said earlier in this chat.

/cortex start
/cortex start --from-chat-start

/cortex all

asks firstsafe to re-run

Backfills every past chat in this folder that isn't tracked yet.

  • It reads the ledger, lists the gaps, and shows a plan: chats to read (with dates and the first line of each), what's excluded, what's already done.
  • Big histories are read by parallel helpers, at most 5 at once.
  • The ledger is updated after each chat, so an interrupted run continues where it stopped.
  • If nothing is missing, it says "nothing to do".
/cortex all
/cortex all since 2026-10-30
/cortex all last 3
/cortex all exclude "the chat about my tax questions"
/cortex all include-skipped --yes

/cortex save

checkpoint

Saves everything now: session log, topic files, changelog, index and ledger.

  • Chats already save themselves before you clear or switch. Use this before a risky step, or when you want certainty.
  • With a note, it stores just that note, even while the chat is paused.
/cortex save
/cortex save "we chose canary at 10% because judges watch the error rate"

/cortex upgrade

asks firstonce per project

Moves a project to the current rules and layout. Memory content is kept; only its format changes.

  • Backs up CLAUDE.md, the index, preferences and protocol first.
  • Copies the rules into memory/RULES.md. Rebuilds the index as a map without losing a single word from the old tables. Swaps the CLAUDE.md block for a 6-line stub.
  • Refuses while another chat in the project is open, because that chat still follows the old rules.
  • Later, if the skill's rules change, it shows the diff and refreshes RULES.md.
/cortex upgrade

Control what's recorded

/cortex pause

this chat--project: all chats

Stops recording. Memory can still be read.

  • Default, this chat only: new chats still record normally. The pause is stored in the ledger, so it holds even after the chat's context is compacted.
  • --project: no chat in this project records until you run /cortex resume --project. New chats remind you once that recording is off.
  • The paused stretch stays out of memory for good, unless you use include-skipped.
/cortex pause
/cortex pause --project

/cortex resume

Starts recording again. In this chat by default, or project-wide with --project (which restores the mode you had before).

/cortex resume
/cortex resume --project

/cortex exclude <chat>

asks first

Permanently leaves a chat out of memory. Name it by ID, date or description.

  • To match a description, it looks only at each chat's first message.
  • If the chat was already captured, it shows what came from it and offers to delete it from memory.
/cortex exclude cb4da6bb
/cortex exclude 2026-10-25
/cortex exclude "the chat where I tested API keys"

/cortex include <chat>

Undoes an exclusion, or lets skipped or paused parts back in. It marks them as gaps and offers to backfill just that chat.

/cortex include cb4da6bb

/cortex forget <topic>

asks first

Removes specific knowledge, such as an outdated decision or something you'd rather not keep.

  • It shows every match with its file and line, and the exact edits it proposes.
  • The changelog notes "forgot <topic>" without repeating the content.
/cortex forget "old pricing assumptions"

/cortex config

Shows or changes this project's settings. Run it with no arguments to see the current values.

Look and check

/cortex status

Changes nothing; the reply is the dashboard only. It shows activity, the memory budget and rules version, routing quality (topic files missing from the map, how many facts carry sources), the self-test trend, what's current and what's next, ledger totals, when this chat last saved, settings, anything needing attention, and one suggested next step.

/cortex recall <question>

Answers from memory with sources, digging deeper layer by layer: index, topic files, session logs, then raw chats. It never looks at excluded or paused parts.

/cortex recall why did we pick SPECTRUM?

/cortex audit

A deeper health check: does the map match the files, are caps respected, are there duplicates, facts that no longer match the code, or gaps in coverage? It proposes fixes and applies them on your OK. Most upkeep now happens on its own, so run it when you want a full review.

/cortex selftest

Quizzes memory now, instead of waiting for the automatic run: a fresh agent answers questions about recent decisions, rejected options and old findings using only memory, and every miss is repaired. See Self-improvement.

/cortex help lists all commands, with a 3-line status.

Memory that improves itself

Every time memory fails to answer something, CORTEX fixes the reason it failed, not just the answer. You don't run anything for this. It learns from three signals, and each one leads to the same question: why didn't memory have it?

From your corrections (free)

When you say "no, it's X" or "we already decided that", Claude fixes the fact in its topic file and then fixes why memory missed it, in the same turn. It adds a changelog line recall miss: …, so you can count what it has learned. While recording is paused it writes nothing and suggests /cortex save instead.

The automatic self-test

After 5 session logs change (at most once a day), the start-up hook asks for a self-test. Recent decisions, rejected options and findings, plus two facts from the oldest logs, become questions. A fresh background agent answers using only memory while you keep working. Then Claude grades the answers and repairs every miss, and any weak spot the agent noticed.

What it never does

Learning edits memory only: topic files, the map, preferences. It never changes the rules (memory/RULES.md), so every project behaves the same, and it never touches your code. The self-test costs about one short agent run. Turn it off with /cortex config selftest=off.

What you see

learning   self-test 7/9 → 8/9 → 9/9 (last 2026-11-02)  ·  next self-test after 3 more changed logs  ·  4 corrections learned

The self-test says nothing in chat. Its result is the learning row of /cortex status, and the files it repaired show in the synced line. The score trend in this example is illustrative.

When memory shapes an answer

Claude stays quiet about memory work, with one exception. When an answer depended on something you didn't say in this chat, the reply ends with a recall line. It shows what memory supplied, how much of it, how deep it had to dig, and whether to trust it.

◈ recalled · L2 · ~6 lines · 12w · Kafka rejected as event bus: ops burden for a team of four
◈◈◈ recalled · L1–L2 · 6 sources · ~420 lines · Aug–Oct · search: OpenSearch, 3 shards, 180 ms p99, BM25-only rejected
◈ recalled · L1 · 6w · superseded · fraud scoring: Stripe Radar → in-house model
◈ ◈◈ ◈◈◈How much memory the answer drew on, by sources or lines read, whichever is larger: a small single recall, ~50–300 lines or 2–3 sources, or over ~300 lines or 4+ sources. A source is one topic file, session log or past chat.
~420 linesAbout how much memory was read for this answer from topic files, session logs and chats. It's an estimate, hence the ~.
+ 2 from L0Lines of the always-loaded index whose content went straight into the answer, such as a status bullet. Lines that only pointed the way, and your preferences, aren't counted.
L0 … L3How deep it dug: the always-loaded map (L0), a topic file (L1), a session log (L2), or a raw chat (L3). A range like L1–L2 means several layers.
12w or 6 sources · Aug–OctFor one memory, how long ago it was decided or recorded. For many, how many sources and the time span they cover.
superseded · unverified · staleGiven a line of its own so it isn't buried: a newer decision replaced an older one, the fact has no source, or a status (something temporary, like "A/B running") is more than 14 days old. Decisions and facts never go stale just by age. That's your cue to double-check.

The gist is up to 12 words for one source and 20 for many; the detail is in the answer itself. Ask "show me what you recalled" to see the full text with its sources. Routine answers, your preferences and the rules never get a line, so a recall line means memory changed the answer.

The ledger: why nothing is processed twice

memory/LEDGER.md has one row per chat, recording which line ranges are already handled. /cortex all reads only the parts that aren't covered. You can open the file and read or edit it like any table.

FAQ

Do I have to re-run /cortex all for new chats?

No. It's a one-time backfill. With auto recording, new chats record themselves. Re-run it only if chats happened in manual mode without start, or after you include something that was excluded or skipped. Re-running is cheap: it only handles gaps.

What do the hooks do? Do they turn CORTEX on everywhere?

They're two automatic reminders. When a chat starts, Claude is told which chat it is, whether anything from a recent chat is missing, and whether memory needs tidying or a self-test is due. After each reply, Claude gets a nudge if it hasn't saved for a while. They never save anything themselves; a hook can only ask, and Claude does the work. They only act in folders where CORTEX is set up (memory/ exists); everywhere else they do nothing. CORTEX only turns on in a project when you run /cortex start or /cortex all there. Without hooks CORTEX still works, just without these automatic reminders.

Does recovery save chats that weren't recording?

No. Recovery only finishes chats that were recording but closed before saving their last part. Chats that never recorded (before CORTEX, in manual mode, or while paused) are left alone. The start hook just mentions them, and nothing from them is saved unless you run /cortex all, which shows a plan and asks first.

Does /cortex start exclude my earlier chats?

No. Other earlier chats stay untracked: not saved and not excluded, so /cortex all can still save them later. The earlier part of the same chat (before you typed /cortex start) is marked skipped; use --from-chat-start to include it from the beginning. A chat is only excluded when you run /cortex exclude.

Does /cortex pause carry over to new chats?

No. It applies only to the chat you're in. Use --project to pause the whole project.

Is memory shared between projects?

No. Each project folder has its own memory/, and you set it up once per folder. The skill itself is installed once, for all projects.

Will my memory end up in git?

Not by default: memory/ is added to .gitignore. Session logs can quote your messages, so commit only if you want teammates to see them (/cortex config commit=yes). Teammates who clone without it get an offer to set up their own.

Does it cost a lot of tokens?

Very little. Each chat starts with the rules (about 1.8k tokens, fixed) plus your memory map and preferences (about 1.7k on a busy hackathon project, about 4.3k on a stress-test project with 720 chats, and a 7k backstop). Each memory update is a small edit, usually 50–300 tokens. Backfilling a large history is a one-time cost: one project's ~25 MB of chats took about 4 helpers and 10 minutes. The automatic self-test costs about one short agent run, at most once a day.

Will the always-loaded memory keep growing?

No. It's bounded by structure, not by trimming. The map stays detailed, because that's how Claude finds old and subtle things, but history is kept at decreasing resolution. The newest 15 session logs have their own line; older ones are covered by up to 4 week lines, 6 month lines, then quarter lines, each a short index of rejected options, decisions and distinctive topics. Each log's full line stays in sessions/README.md, one hop away. A folder with more than 10 files becomes one summary line of its key nouns, with the details in its _index.md. In a stress test with 720 chats over 90 days this came to about 4.3k tokens and answered 14 of 14 tricky recall questions. A flat layout used about 1k tokens but kept missing a 6-week-old rejected option.

Will it still find something from weeks ago?

That's what the layers are for. Each session log on the map lists its topics, decisions and rejected options, so a "why did we…" question goes straight to the right log, and Claude reads just the matching lines. Rejected options are also copied into their topic file. The self-test keeps quizzing facts from the oldest logs, so if something old becomes unreachable, it gets noticed and fixed.

What does it store, and what does it skip?

The test is "would a future chat be better informed for having this?": decisions and reasons, your requirements and corrections, findings, explanations, numbers and caveats, ideas, bugs and fixes, status. Subtle details go to the session logs. It drops chit-chat, retries and duplicates, and never stores secrets, keys, passwords, or anyone's email or phone number.

What if memory and the code disagree?

On what the system does, the code wins. On what you want, your latest instruction wins. The stale memory is corrected on the spot, and unconfirmed facts are labelled "not yet verified".

To remove CORTEX from a project: delete the block between <!-- CORTEX:BEGIN and <!-- CORTEX:END --> in CLAUDE.md, then delete memory/ if you want the memory gone. To uninstall the skill: run ./install.sh --uninstall-hooks from the CORTEX repo (it backs up settings.json first), then delete ~/.claude/skills/cortex/.

Not covered here: the build and upgrade procedure (reference/build.md) and the exact rules each chat follows (reference/rules.md). Read those to change how CORTEX behaves.
